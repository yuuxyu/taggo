# taggo 要件定義書

## システム概要・アーキテクチャ方針

- **メタデータ保持方針**
  - ローカルファイルのメタデータ領域（Exif / ID3 / YAML Front Matter）を正（Single Source of Truth）として扱う。
  - アプリによるタグ変更は、実ファイル領域へ直接書き込み・更新する。
- **データベース・検索方針**
  - Pure Go 製の完全インメモリ KV ストア「BuntDB」を採用する。
  - ディスクへのデータベース永続化（.db ファイル保存）は行わない。
  - アプリ起動時およびフォルダ選択時に配下ファイルを走査し、BuntDB へデータを展開して高速なメモリ内検索を提供する。
- **UI・デザイン方針**
  - 「最上部検索バー ＋ カード型グリッド（カード内にタグバッジ配置）」をメイン画面とする。
  - アプリ内ではフォルダのような階層構造を持たせず、ファイルを最小粒度としたフラット管理をベースとする。
  - ファイル同士の依存関係で検索、可視化できるようにする。
  - スタイルは Tailwind CSS のユーティリティで組み立て、独自の CSS は配色トークンと
    要素の既定値に限る。アイコンは Heroicons を用い、配色は OS のテーマ設定に追従させる。

## 画面要件

- **検索バー（最上部固定）**
  - アプリ起動時に検索バーへ自動でフォーカス（キャレット配置）を当てる。
  - 1 文字入力ごとに追従するリアルタイム（インクリメンタル）検索を提供する。
  - `#` を入力した際、BuntDB 内の登録済み全タグのオートコンプリート（候補表示）ドロップダウンを出力する。
- **カード型ビジュアルグリッド**
  - 走査された全ファイルをサムネイル／プレビュー付きの「カード」としてグリッド表示する。
  - 画像ファイル：高解像度サムネイルを表示する。
  - Markdown ファイル：ファイル冒頭テキストおよび見出しのプレビューを表示する。
  - 音声ファイル：波形イメージまたは音声トラック情報アイコンを表示する。
  - 各カードの下部に埋め込みタグをバッジ（`#tag`）として一覧表示する。
- **インタラクション＆操作性**
  - カード上の「#タグバッジ」をクリックすると、そのタグが検索バーに挿入され、即座に該当タグで絞り込まれる。
  - カードをクリックすると、画面遷移なしで詳細プレビューを開く。
  - 大量ファイル描画時の遅延を防ぐため、仮想スクロール（Virtual Scroll）を採用する。

## コア機能要件（In-Scope）

### タグ管理

- **ファイル内埋め込みメタデータ（タグ）編集**
  - Markdown (`.md`): YAML Front Matter (`tags: [tag1, tag2]`) の書き換えを行う。
  - 画像 (JPEG, PNG, WebP): Exif / XMP メタデータの書き換えを行う。
  - 音声 (MP3, FLAC, WAV): ID3v2 / Vorbis Comment メタデータの書き換えを行う。
  - 実ファイルの書き込み成功時、BuntDB 上のメモリ内データ（JSON）を即座に更新・再インデックスする。
- **BuntDB によるインメモリタグ抽出＆検索**
  - 指定ルート配下を非同期スキャンし、BuntDB へデータ投入する（Key: ファイルパス, Value: メタデータ JSON）。
  - BuntDB のカスタムインデックスを利用し、複数タグの AND / OR / NOT 検索および更新日時順ソートを提供する。
  - File Watcher による変更検知時、BuntDB 上の該当レコードを自動で同期更新・削除する。
- **複数ファイル選択時の一括（バルク）埋め込みタグ編集機能**
  - メイン画面で複数ファイルを選択でき、一括でタグ編集できる機能を提供する。

### プレビュー機能

- **Markdown ドキュメントプレビュー**
  - CommonMark / GFM (GitHub Flavored Markdown) 規格に準拠してレンダリングする。
  - 冒頭の Front Matter 部分を本文から除外し、ヘッダーに「タグバッジ」として分離表示する。
  - コードハイライト、テーブル表示、mermaid をサポートする。
  - 本文から相対パスで参照された画像（`![](./img/a.png)` 等）を、Markdown ファイルの位置を
    基準に解決して表示する。`/` 始まりは開いているフォルダを基準とする。
  - Markdown ファイル間の内部リンク（`[[WikiLink]]` 等）のメモリ内グラフ保持とバックリンク表示を提供する。
- **マルチフォーマット画像プレビュー**
  - 対応フォーマット：PNG, JPEG, WebP
  - 拡大・縮小、フィット表示制御を提供する。
  - メタデータパネルにて、タグ情報に加え撮影日時・解像度・機器情報を表示する。
- **メディアオーディオプレイヤー**
  - 対応フォーマット：MP3, WAV, FLAC
  - ID3/Vorbis タグから楽曲名、アーティスト名、アルバムアート、タグ情報を抽出し表示する。
  - 再生/一時停止、シークバー操作、音量調整、ミュート、ループ再生制御を提供する。
  - 音声再生時のインタラクティブな波形表示およびタイムスタンプジャンプ機能を提供する。

## 実装しない機能・スコープ外

- **データベース・永続化関連**
  - BuntDB のディスク永続化（AOF/RDB）は行わず、アプリ終了時にメモリは破棄する。
  - RAM の過剰消費を防ぐため、1 度のスキャンで BuntDB に展開するファイル件数に上限（例: 最大 2 万件）を設ける。
- **UI・ファイル操作関連**
  - 従来の OS のような「階層型ツリー（フォルダーツリー）」は排除し、タグと検索によるフラットな閲覧に特化する。
  - ドラッグ＆ドロップによるカードの手動自由配置はサポートせず、更新順・名前順・関連度順の自動ソートのみとする。
  - 読み取り専用・プロテクト指定ファイルへのタグ編集は行わず、エラー表示とする（メモリ上のみ一時更新する不整合処理は行わない）。
  - 画像加工・動画変換・本文編集など、メタデータ領域外の本体データに対する編集・加工機能は実装しない。
- **対応フォーマット関連**
  - GIF・SVG・AAC・M4A はタグの標準的な埋め込み場所を持たず実装コストに見合わないため対応しない。
    拡張子と中身が食い違うファイルの中身がこれらだった場合は、AVIF/HEIC 等と同様に
    読み取り専用として理由を表示する。
