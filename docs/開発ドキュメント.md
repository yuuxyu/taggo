# 開発ドキュメント

## 動かし方

taggo は Windows 専用です。動作を確かめられるのが Windows だけのため、ほかの OS 向けのコードは持ちません。

### 必要なもの

- Windows 10 以降
- Go 1.26 以上
- Node.js 20 以上
- [Wails CLI](https://wails.io/) v2

```sh
go install github.com/wailsapp/wails/v2/cmd/wails@latest
```

### ビルドと実行

```powershell
make build                  # build/bin/taggo.exe を作る
.\build\bin\taggo.exe       # 起動する

.\build\bin\taggo.exe --folder C:\Users\me\Documents\notes   # フォルダを指定して起動する
```

開発中はホットリロードが使えます。

```sh
make dev
```

なお `wails dev` は GET をすべて Vite の開発サーバーへ転送し、開発サーバーが 404 か 405 を返したときにだけ Go 側のハンドラーへ委譲します。

Vite は未知のパスへ SPA フォールバックで `index.html` を 200 で返してしまうため、`frontend/vite.config.ts` のプラグインで `/taggo/` 以下だけを 404 にして、本文中の画像の配信要求が Go 側へ届くようにしています。

#### make のインストール

標準の Windows には `make` が入っていないため、以下の手順でインストールします。

```powershell
# GNU Make を入れる
winget install GnuWin32.Make
# インストール後、C:\Program Files (x86)\GnuWin32\bin を PATH に追加する
```

### テスト

```sh
make test   # Go のテスト
make lint   # gofmt / go vet / tsc --noEmit
```

### リリース

バージョン番号は [セマンティックバージョニング](https://semver.org/lang/ja/) に従います。`v1.2.3` の形式（プレリリースは `v1.2.3-rc.1`）のタグを push すると、GitHub Actions（`.github/workflows/release.yml`）が Windows 向けの exe をビルドし、GitHub のリリースへ添付します。

1. `CHANGELOG.md` の先頭に新しいバージョンの節（`## [1.2.3] - 日付`）を足し、末尾にそのリリースへのリンクを書く（この節がリリースノートになる）
2. `wails.json` の `info.productVersion` を新しいバージョンにする（ローカルビルド用。Actions ではタグの値で上書きする）
3. コミットしてタグを付け、push する

```sh
git tag v0.1.0
git push origin main v0.1.0
```

- タグが SemVer の形式でないとき、`CHANGELOG.md` にそのバージョンの節が無いとき、テストが落ちたときはリリースを作りません。
- `-` を含むタグはプレリリースとして公開します。

## 設計

- 一覧・検索・タグ管理の対象は、開いたフォルダの直下にある Markdown（`.md` / `.markdown`）だけです。走査もウォッチャーもサブフォルダの中と Markdown 以外のファイルは無視します（ウォッチャーは例外として `.taggo.json` の変更を拾います）。
- ノートのファイル名（拡張子を除く）がタグを表します（`model.PageTag`）。store はタグのキー（`model.TagKey`。小文字にして空白の連なりをまとめたもの）からそのページを引く索引 `tagPages` を持ちます。サブフォルダを読まないのは、同じ名前のページがフォルダ違いで並ばないようにするためです。
- ノートのタグは、本文の `[[タグ]]`（`meta.bodyTags`。コードブロックとインラインコードの中は除く）だけを `model.Entry.Tags` に入れます。Front Matter は使いません。先頭の `---` で囲んだブロックは、見出しや抜粋に紛れ込まないよう `meta.StripFrontMatter` で本文から外すだけで、中身は読みません（YAML のライブラリも使っていません）。
- ノートの本文は、編集画面（`frontend/src/editor/`）で書いた Markdown をそのまま保存します。タグ専用の編集機能は持ちません。ファイルを新しく作るのは「まだ無いページ」か検索結果の上の作成ボタンから md ファイルを作るとき、編集画面に画像を貼り付けたとき、`.taggo.json` だけです。既存のノートに書き込むのは、編集画面の保存とページの名前の変更だけです。
- 編集画面は [CodeMirror 6](https://codemirror.net/) のライブプレビューです。ファイルの中身は Markdown のままにして、見た目だけを装飾（Decoration）で整えます。文書として編集して Markdown へ書き戻す方式にしないのは、保存のたびにリストの記号や空行が書き換わり、ノートに意図しない差分が出るためです。
  - `NoteEditor.tsx` が CodeMirror を 1 つだけ作り、ノートを開くたびに中身（`EditorState`）を差し替えます。画面側の受け口（リンクをたどる・画像を開くなど）は `host.ts` の `hostFacet` に ref で渡し、拡張やウィジェットは使う時点で最新の受け口を読みます。
  - 構文は `@codemirror/lang-markdown`（GFM）に、`[[タグ]]` を読む `BracketTag` を足したものです（`syntax.ts`）。読む規則は Go 側の `meta.bodyTags` と合わせてあります。
  - `livePreview.ts` が、構文木から見た目を作ります。行の中で完結するもの（見出しの大きさ、記号を隠す、リンクの色、画像・チェックボックス）は見えている範囲だけを `ViewPlugin` で、行ごと置き換えるもの（表・mermaid の図・リンクカード）は CodeMirror の決まりで `StateField`（`blockField`）から渡します。カーソル（選択範囲）がかかっている要素や行は記号を隠さず、フォーカスが外れている間はすべて隠します（`focusedField`）。改行をまたいで隠すことはできないので、置き換えは行の中に限ります。
  - 表と mermaid は React の部品（`MarkdownBlock`・`Mermaid`）を、URL だけの行は `LinkCard` をウィジェットの中に描きます（`widgets.tsx` の `ReactWidget`）。
  - リンクカードは、段落ではなく行で見ます（文書の直下の段落の中で、URL か `<URL>` だけの行）。行の中のウィジェットにすると、CodeMirror がカーソル用に前後へ置く要素がブロック表示のカードの下に空の行を作るので、行ごとのブロック（`block: true`）として置き換えます。
  - `blockField` は置き換えの候補（表・mermaid・URL だけの行）を本文が変わったときだけ集め直し、カーソルが動いたときは集めた候補から装飾だけを作り直します。CodeMirror は上下キーの移動で行ごとのブロックを飛ばすので、隣の行が候補なら、その行の端へカーソルを置くキー割り当て（`enterBlock`）を足しています。
  - 本文の装飾は Tailwind のクラスで付けます。CodeMirror が自前で描く部分（枠・カーソル・補完の一覧）と構文ごとの文字の色は `theme.ts` にまとめています。行の余白は土台で 0 にしているので、行に付ける余白のクラスには `!` を付けて優先させます。
  - 入力の補完は `markup.ts`（`**` の対、``` + Enter の閉じフェンス、Ctrl + B / I、リストの続き）と `completion.ts`（`[[` のタグ候補と ``` の言語名）です。タグの候補は Go 側の `App.TagNames`（`store.TagNames`）から取り、しばらく覚えておきます。
  - 画像の貼り付けとドロップは `pasteImage.ts` が受け、Base64 にして `App.SaveImage` へ渡します。Go 側は中身から形式を判定し（`imagefile.Sniff`）、フォルダ直下へ日時の名前で `O_EXCL` で作ります。保存を待つ間は仮の記述を入れておき、保存できたら差し替えます。仮の記述はファイルには書きません。
- 保存は `App.ReadNote` / `App.SaveNote` の 2 つです。
  - `ReadNote` はファイルの中身（Front Matter も含む。先頭の BOM だけ除く）と、中身の SHA-256 を `Version` として返します。
  - `SaveNote` は渡された `Version` と今のファイルの中身を照らし合わせ、違えば書き込まずに `Conflict` を返します。空の `Version` は確かめずに上書きします（利用者が上書きを選んだとき）。元のファイルに BOM があれば付け直し、中身が変わらなければ書き込みません。書き込みは `atomicfile.Replace` で、ウォッチャーを待たずに DB を直して `entry:changed` を送ります。名前の変更と同時に走らないよう、`App.writeMu` で 1 つずつにします。
  - 画面は入力が止まって 1 秒で保存し、ノートを移るとき・フォーカスが外れたとき・名前の変更の前・「エディタで開く」の前にも保存します（`flushAllEditors`）。改行は読んだファイルに合わせて戻します（CodeMirror の中では `\n` にそろう）。
  - ウィンドウを閉じるときは、Wails の `OnBeforeClose`（`app.OnBeforeClose`）が一度だけ閉じるのを止めて `app:beforeClose` を送ります。画面は保存を終えてから runtime の `Quit` を呼び直し、2 回目はそのまま閉じます。画面が応答しなくても 5 秒で閉じます。
  - ほかのアプリでの保存は、ウォッチャーが届けるエントリの更新日時とサイズで気付きます。自分の保存の結果で覚えた値と違えば `ReadNote` で確かめ、書きかけが無ければ変わったところだけを差し替え、書きかけがあればぶつかっていることを画面に出します。保存の途中に届いた知らせは、保存が終わってから確かめます。
- ページの名前の変更は、`App.PlanRename`（書き換わるノートを調べるだけ）と `App.RenamePage`（実行）の 2 段階です。画面（`RenameDialog`）は前者の結果を見せてから後者を呼びます。
  - 対象は `os.ReadDir` で列挙したフォルダ直下のすべての Markdown です。読み込みの上限で DB に載っていないノートも参照を残さないよう含めます。
  - 参照の書き換えは `meta.RenameRefs` が行います。`[[タグ]]` の読み取り（`meta.bodyTags`）と同じく、コードブロック・インラインコード・Front Matter の中は触りません。Markdown のリンクがそのページを指すかは、リンク元の位置から `store.LinkPath` で解決して `store.SameNote` で比べます。
  - `RenamePage` は先にすべてのノートを読んで書き換え後の中身を作り、読めないノートがあれば何も変えずに断ります。そのあとファイル名を変え（`os.Rename`）、各ノートを `atomicfile.Replace`（一時ファイルに書いてから置き換える）で書き換えます。
  - DB はウォッチャーを待たずにその場で付け替え、`entry:renamed` イベントを送ります。画面は、一覧（`useLibrary`）・移動の履歴（`useNavHistory.renamePath`）・一覧の外のエントリを新しいパスへ付け替えます。古いパスの削除イベントは送らないので、開いていたページは閉じずに新しい名前で開いたままになります。
- 本文のリンクは 3 種類に分けて見せます（見た目のクラスは `frontend/src/links.ts`）。`[[タグ]]` とノートへのリンクはアプリの中でたどるので下線を付けず（`INTERNAL_LINK`）、`http(s):` と `mailto:` の外部リンクは下線と末尾の「↗」を付けて（`EXTERNAL_LINK`）、既定のブラウザで開きます（`BrowserOpenURL`。`target="_blank"` だと WebView2 が自前のウィンドウを開くため）。WebView にはステータスバーが無いので、行き先はツールチップで見せます。編集画面では、カーソルを動かす前に受けたいので `mousedown` でたどります。
- 表を HTML に描き直す `MarkdownBlock` では、`[[タグ]]` を remark プラグイン（`frontend/src/bracketTags.ts`）がリンクに変え、`data-tag` 属性でふつうのリンクと見分けます。
- 下端の文字数は、`NoteEditor` が渡す本文（Front Matter を除く）を `DetailPanel` が数えます。入力のたびに数えないよう少し間を置きます。改行は数えず、絵文字や結合文字が 2 文字以上にならないよう `Intl.Segmenter` で書記素ごとに数えます。
- まだ無いページ：`[[タグ]]` や行き先の無い Markdown のリンクをたどると、`App.TagPage` / `App.LinkedPage` が「まだ無いページ」のエントリ（`model.NewMissing`。`Missing` が true で、BuntDB には載せない）を返します。画面はそれを一覧の外のノートとして開き、本文の代わりに「md ファイルを作成する」ボタンを出します。検索結果の先頭にタグのページが無いとき（`Result.Head` が 0）も、画面は検索語で `App.TagPage` を呼び、まだ無いページが返れば結果の上に作成ボタン（`NewTagPageBar`）を出します。
  - `App.RelatedPages` は、まだ無いページのパスでも `store.Related` に仮のエントリを渡すので、そのページを指しているノート（リンク元）が並びます。
  - ボタンは `App.CreatePage` を呼び、見出しだけのファイルを作って、ウォッチャーを待たずに DB へ載せ、`entry:changed` を送ります。同じパスのエントリが届くので、画面は開いているページを本物のノートの編集画面に差し替え、本文の末尾にカーソルを置きます（`requestEditorFocus`）。
  - 扱うパスは開いているフォルダ直下の `.md` / `.markdown` に限ります（`App.checkPagePath`）。ファイル名に使えないタグは `model.TagFileName` で断ります。
- Markdown の本文が正（Single Source of Truth）です。アプリ側にデータベースを保存しません。
- 検索は Pure Go の [BuntDB](https://github.com/tidwall/buntdb) をインメモリで使い、起動時・フォルダ選択時にフォルダ直下の Markdown を走査して展開します。終了時にメモリごと破棄されます。
  - 検索バーの文字列は、空白で区切った語の並びとして読みます（`internal/search`）。語をすべて含むノートが結果で、条件式や `#タグ` の記法はありません。
  - 入力全体がタグのキーと一致するときは、そのタグのページを `Result.Entries` の先頭に置き、その件数を `Result.Head` で返します。検索語が無いときは、ピン留めしたノートを同じように先頭に置きます。グリッド（`CardGrid`）は先頭の `Head` 件と残りを別の行に並べます。
- 本文中の画像は DB に載せず、`/taggo/image?path=…` で配信します。配信するのは、開いているフォルダ配下（シンボリックリンクの実体も含めて確かめる）にあり、先頭バイトから判定した形式がブラウザで表示できる画像（`internal/imagefile`）のファイルだけです。拡張子は見ません。中身がクラウド上にしか無い画像は、配信のために読んだ時点で同期サービスがダウンロードします。
- カードのサムネイル（`model.Entry.Thumbnail`）は走査時に本文から取り出します。コードブロックの外で最初に現れる Markdown の画像（ローカルのパスか http(s) の URL）か YouTube 動画の URL で、画像は書かれたままのパスを持ち、YouTube は動画 ID から `https://i.ytimg.com/vi/<ID>/mqdefault.jpg` を組み立てます。ノートからの相対パスの解決は編集画面と同じ `frontend/src/notePath.ts` で行い、ローカルの画像は `/taggo/image` で配信します。読み込めなければカードは本文の抜粋に戻ります。
- カードのタグ欄は高さを 4 行ぶんに決めてあり、何個収まるかは描画してから実際にあふれているかを測って決めます（`Card.tsx` の `CardTags`）。収まらない分は「+N」で数を示し、タグ欄に乗ると全部を重ねて見せます。
- 本文中の画像をクリックすると、`DetailPanel` の上に `ImagePreview` を重ねて開きます。画像はノートではないので履歴（`useNavHistory`）には積まず、閉じると同じスクロール位置の本文へ戻ります。
- RAM の消費を抑えるため、1 回の走査で展開する件数に上限（2 万件）を設けています。上限を超えたフォルダは走査順（フォルダ直下のファイル名の順）の先頭だけを読み込み、最後に読んだファイルの相対パスを再開位置として覚えます。「続きを読み込む」ではその位置から次の分を走査し、今の DB へ追記します。
  - 上限に達したあともディレクトリの列挙だけは最後まで続け、残りの件数を数えます。上限を超えた分のファイルは開かないので、クラウド同期フォルダでもダウンロードは起きません。
  - ウォッチャーは、再開位置より後ろ（まだ読み込んでいない範囲）のファイルの変更を無視します。そうしないと、その 1 件だけが一覧に紛れ込むためです。
- ファイルウォッチャーが外部エディタによる変更も検知し、該当レコードを同期・削除します。
- 設定（`internal/settings`）は `%APPDATA%\taggo\settings.json`（`os.UserConfigDir()` の下）に JSON で保存します。持つのは起動時に開くフォルダ・一覧の既定の並び順・走査の上限件数・テーマだけで、消えても既定値に戻るだけのものに限ります。
  - 設定を一度も保存しなければファイルは作りません。前回開いたフォルダ（`lastFolder`）は、起動時のフォルダを「前回開いたフォルダ」にしているときだけ `OpenFolder` のたびに書き込みます。
  - 書き込みは同じフォルダの一時ファイルへ書いてから置き換えます。読み込み時に知らない値や範囲外の値は項目ごとに既定値へ直し、JSON として壊れていれば `settings.json.bak` へ退避して既定値で起動します。
  - 起動時に開くフォルダは、コマンドライン引数 → 設定 → 何も開かない、の順に決めます（`App.OpenStartupFolder`）。フォルダが見つからないなどの警告は、起動フックの時点では画面がイベントを受け取れないため、画面から `TakeStartupWarnings` で取りに来てもらいます。
  - 並び順とテーマを最初の描画から反映するため、フロントエンドは設定を読んでから React を描きます（`main.tsx`）。
- 関連ページ（`store.Related`）は、グループ（`RelatedGroup`）の並びとして返します。リンク元のグループ（開いているノートが表すタグを持つノート `tagged` と、Markdown のリンク元 `backlinks` を合わせたもの）、付いているタグごとのグループ（タグの順）、Markdown のリンク先のグループの順です。
  - タグのグループは、先頭にタグのページ（`Page`。まだ無ければ `Path` が空）、後ろにそのタグを持つノート（逆引き索引 `tagged`）を、開いているノートと重なるタグの多い順・更新日時の新しい順に並べます。
  - 並べたノートは「表示済み」として覚え、後のグループには出しません。1 グループは `groupLimit`（24 件）までで、超えた分は `More` に数だけを入れます。
  - 本文の色分けに使う、行き先の無いリンク（`MissingLinks`）とページの無いタグ（`MissingTags`）は、グループとは別に返します。後のグループで表示が省かれても、本文の色が変わらないようにするためです。
  - 画面（`RelatedPages`）は本文の下に、グループごとのカードのグリッドとして描きます。カードの抜粋・サムネイルは一覧のカードと同じ `NotePreview` を使います。
- ピン留めは開いたフォルダ直下の `.taggo.json`（`internal/folderconf`）にファイル名の並びとして保存します。フォルダの Wiki の見せ方なので、`%APPDATA%` ではなくノートと一緒に置いています。
  - 書き込むときは毎回ファイルを読み直し、taggo の知らない項目は残します。JSON として壊れていれば書き換えずにエラーにします。一時ファイルは `.taggo.json.taggo-XXXX`（ノートの書き換えでは `.<ファイル名>.taggo-XXXX`）で、ウォッチャーは自分の書き込みとして無視します（`atomicfile.IsTemp`）。
  - ウォッチャーが `.taggo.json` の変更を拾うと読み直し、`pins:changed` イベントで画面に引き直させます。
- クラウド同期フォルダの「オンラインのみ」のファイルは見分けません。フォルダ直下のノートは走査で読み、本文の画像は表示するときに読むので、その時点で同期サービスがダウンロードします。読まないのは、サブフォルダの中・本文が参照していないファイル・読み込みの上限を超えた分です。
- 起動時に、プレースホルダーを通常ファイルとして見せる設定（`RtlSetProcessPlaceholderCompatibilityMode`。`internal/cloudfile`）へ固定しています。もう一方の設定ではプレースホルダーに REPARSE_POINT 属性が付いて見え、`os.Stat` が属性を問い合わせるだけで済まず、ファイルを開きに行くためです。
- リンクカードの内容は Go 側（`internal/linkcard`）で取得します。WebView からは CORS のため他サイトの HTML を読めないためです。接続先は名前解決後のアドレスで判定し、ローカルネットワークには接続しません。YouTube は地域によって同意画面へ飛ばされ、X はブラウザ以外に OGP を返さないため、この 2 つは oEmbed を使います。
- 画面のスタイルは Tailwind CSS のユーティリティで組み立てています。独自に書く CSS は `frontend/src/styles/global.css` の配色トークン（`@theme`）と要素の既定値だけです。配色は `frontend/src/theme.ts` が `<html data-theme="light|dark">` を付けて切り替え、トークンと Tailwind の `dark:` バリアントはこの属性を見ます。テーマが「OS に合わせる」のときは OS の設定を解決した値を入れ、OS の切り替えにも追従します。タイトルバーの配色は Go 側（Wails の `WindowSet*Theme`）で合わせます。アイコンは [Heroicons](https://heroicons.com/) を使っています。

### パッケージ構成

| パッケージ           | 役割                                                 |
| -------------------- | ---------------------------------------------------- |
| `internal/model`     | 共有するデータ型とタグの正規化・ファイル名とタグの対応 |
| `internal/meta`      | Markdown の本文からタグ（`[[タグ]]`）・見出し・抜粋・リンクを読み取る。名前を変えたページへの参照を書き換える |
| `internal/store`     | BuntDB への展開と検索・タグ索引・リンクの関連付け・ピン留めの並び |
| `internal/search`    | 検索バーの文字列を問い合わせへ変換する               |
| `internal/scan`      | フォルダ直下の走査とメタデータの並列読み取り         |
| `internal/watcher`   | ファイル変更の検知                                   |
| `internal/folderconf` | フォルダ直下の設定ファイル（`.taggo.json`。ピン留め）の読み書き |
| `internal/atomicfile` | 一時ファイルに書いてから置き換える書き込み（`.taggo.json` とノートの保存・書き換え） |
| `internal/cloudfile` | クラウド同期のプレースホルダーを通常ファイルとして見せる設定 |
| `internal/imagefile` | 本文中の画像の形式判定（配信・保存してよい画像か）と拡張子 |
| `internal/linkcard`  | リンクカードに出す OGP / oEmbed の取得とキャッシュ   |
| `internal/settings`  | 設定ファイル（`%APPDATA%\taggo\settings.json`）の読み書き |
| `internal/app`       | フロントエンドへ公開する API（ノートの読み書き・画像の保存を含む）と本文中の画像の配信 |
| `frontend`           | React + TypeScript + Vite + Tailwind CSS の UI       |
| `frontend/src/editor` | CodeMirror 6 による編集画面（ライブプレビュー・入力補完・画像の貼り付け・自動保存） |
