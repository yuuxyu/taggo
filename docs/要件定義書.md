# taggo 要件定義書

## システム概要・アーキテクチャ方針

- **コンセプト**
  - Markdown を使った、タグ管理のローカル Wiki デスクトップアプリとする。
  - 一覧・検索・タグ管理の対象は、開いたフォルダの直下にある Markdown のノートだけとする。サブフォルダの中は読まない。画像は Markdown の本文に埋め込んで表示するためだけに扱い、音声は扱わない。
  - ノートのファイル名（拡張子を除く）が、そのままタグを表す。`golang.md` は `golang` タグのページとする。
- **対応環境**
  - Windows 専用とする。動作を確かめられるのが Windows だけのため、ほかの OS には対応しない。
  - クラウド同期サービスは Dropbox で動作を確かめる。
- **メタデータ保持方針**
  - ノートに付くタグは、本文の `[[タグ]]` を正（Single Source of Truth）として扱う。Front Matter は使わない。
  - taggo はノートを書き換えない。タグの付け外しは、利用者がエディタで本文を直して行う。
- **データベース・検索方針**
  - Pure Go 製の完全インメモリ KV ストア「BuntDB」を採用する。
  - ディスクへのデータベース永続化（.db ファイル保存）は行わない。
  - アプリ起動時およびフォルダ選択時にフォルダ直下の Markdown を走査し、BuntDB へデータを展開して高速なメモリ内検索を提供する。
- **設定の保存方針**
  - アプリの好み（起動時に開くフォルダ、一覧の既定の並び順、1 回の走査の上限件数、テーマ）に限り、`%APPDATA%\taggo\settings.json` へ保存する。
  - 保存してよいのは「消えても初期状態へ戻るだけ」のものに限る。タグ・走査結果・キャッシュなど、ノートから導けるものやノートの中身の写しは保存しない。
  - 設定を一度も変えなければ、設定ファイルは作らない。前回開いたフォルダは、起動時に「前回開いたフォルダ」を開く設定にしたときだけ記録する。
  - 設定ファイルが壊れていても既定の設定で起動し、壊れたファイルは上書きせずに退避する。
  - 例外として、一覧のピン留めは、開いたフォルダの直下の `.taggo.json` に保存する。そのフォルダの Wiki の見せ方なので、ノートと一緒に同期・バックアップされるようにするため。taggo の知らない項目は書き込むときも残し、JSON として壊れていれば書き換えない。
- **勝手に通信しない方針**
  - クラウド同期サービスが置いた「中身がまだローカルに無いファイル」は、ファイル属性から判別し、taggo 側からは一切開かない。走査だけで同期フォルダ全体をダウンロードさせない。
  - 該当ノートは一覧には出す（名前・サイズ・更新日時のみ）。タグの読み取り・プレビューは行わず、利用者が明示的に取り込みを指示したときだけ読み込む。
  - 本文に埋め込まれた画像の中身がクラウド上にしか無い場合は、画像を配信しない（ノートを開いただけでダウンロードを始めない）。
  - 走査のあとで「オンラインのみ」へ戻ったファイルも開かないよう、中身を開く直前に属性を確かめ直す。
  - `.taggo.json` の中身がクラウド上にしか無いときは、ピン留めを読み込まない。
  - 属性で判別できない方式は対象外とする。Google ドライブのストリーミング用の仮想ドライブは自動で判定し、読み込みを断る。
  - 例外として、Markdown 本文に URL だけを書いた段落は、プレビューを開いた時点でリンク先からリンクカードの内容を取得する。本文の外部画像と同じく、利用者が本文に書いた URL だけを対象とし、ローカルネットワークのアドレスには接続しない。
  - 例外として、カードのサムネイルが外部 URL の画像か YouTube 動画のときは、一覧を表示した時点でその画像を読み込む。接続先は本文に書かれた画像の URL と、YouTube のサムネイル画像（`i.ytimg.com`）だけとする。
- **UI・デザイン方針**
  - 「最上部検索バー ＋ カード型グリッド（カード内にタグバッジ配置）」をメイン画面とする。
  - アプリ内ではフォルダのような階層構造を持たせず、ノートを最小粒度としたフラット管理をベースとする。フォルダ直下だけを読むので、同じ名前（同じタグ）のノートがフォルダ違いで並ぶことはない。
  - ノート同士のリンク関係で検索、可視化できるようにする。
  - スタイルは Tailwind CSS のユーティリティで組み立て、独自の CSS は配色トークンと要素の既定値に限る。アイコンは Heroicons を用い、配色は既定では OS のテーマ設定に追従させ、設定でライト・ダークに固定できるようにする。

## 画面要件

- **検索バー（最上部固定）**
  - アプリ起動時に検索バーへ自動でフォーカス（キャレット配置）を当てる。
  - 1 文字入力ごとに追従するリアルタイム（インクリメンタル）検索を提供する。
  - 検索は単純な全文検索とする。空白で区切った語をすべて含むノートを結果とし、語はタイトル・ファイル名・本文の抜粋・タグから大文字小文字を区別せずに探す。タグを指定する記法（`#タグ`）や、AND / OR / NOT のような条件式は持たない。
  - 入力全体がタグの名前と一致するときは、そのタグのページ（ファイル名がそのタグのノート）を並び順にかかわらず結果の先頭に出す。
- **カード型ビジュアルグリッド**
  - 走査された全ノートを「カード」としてグリッド表示する。
  - 検索していないときは、ピン留めしたノートをピン留めした順に先頭へ並べ、残りのカードは次の行から並べる。検索中はピン留めを先頭にしない（検索語と同じ名前のタグのページを先頭の別枠とする）。
  - カードには見出しと本文冒頭の抜粋を表示する。
  - 本文で画像か YouTube 動画を使っているノートは、抜粋の代わりに、本文で最初に現れる画像または動画のサムネイルを表示する。画像を読み込めないときは抜粋に戻す。
  - 各カードの下部に、ノートのタグ（本文の `[[タグ]]`）をバッジ（`#tag`）として一覧表示する。2 行に収まらないタグは「+N」と数で示し、タグ欄に乗ったときに全部を重ねて表示する。
- **インタラクション＆操作性**
  - カード上の「#タグバッジ」をクリックすると、そのタグで検索する（そのタグのページが先頭に、タグを付けたノートがその後ろに並ぶ）。
  - カードと詳細プレビューから、ノートを一覧の先頭にピン留めし、また外せる。
  - カードをクリックすると、画面遷移なしで詳細プレビューを開く。
  - 大量ノート描画時の遅延を防ぐため、仮想スクロール（Virtual Scroll）を採用する。

## コア機能要件（In-Scope）

### タグ管理

- **タグの付け方**
  - ノートの本文に `[[タグ]]` と書いたものだけをタグとする。コードブロックとインラインコードの中の `[[ ]]` はタグとして読まない。
  - Front Matter（先頭の `---` で囲んだ YAML）は使わない。`tags:` や `title:` を書いても、タグや見出しにはならない。ほかのツールで書いたノートに Front Matter があれば、プレビューと抜粋からは外して表示する（中身は読まない）。
  - taggo にタグの編集機能は持たせない。タグの付け外しは、エディタで本文を直して行う。
- **タグのページ**
  - ノートのファイル名（拡張子を除く）が、そのタグを表すページとなる。タグとファイル名の突き合わせでは、大文字小文字と空白の連なりを区別しない。
  - 本文の `[[タグ]]` は、プレビューでそのタグのページへのリンクとして表示する。ページがまだ無ければ赤みがかった色で示し、クリックすると「まだ無いページ」として開く（後述）。
  - Windows のファイル名に使えない文字を含むタグには、ページを作らない。
- **ピン留め**
  - ノートを一覧の先頭にピン留めできる。ピン留めは開いたフォルダ直下の `.taggo.json` にファイル名の並びとして保存し、外で書き換えられたときも読み直す。
- **BuntDB によるインメモリタグ抽出＆検索**
  - 指定ルート直下の Markdown を非同期スキャンし、BuntDB へデータ投入する（Key: ファイルパス, Value: メタデータ JSON）。
  - BuntDB のカスタムインデックスを利用し、全文検索および更新日時順・名前順のソートを提供する。
  - File Watcher による変更検知時、BuntDB 上の該当レコードを自動で同期更新・削除する。

### プレビュー機能

- **Markdown ドキュメントプレビュー**
  - CommonMark / GFM (GitHub Flavored Markdown) 規格に準拠してレンダリングする。
  - ノートのタグ（本文の `[[タグ]]`）を、ヘッダーに「タグバッジ」として表示する。
  - コードハイライト、テーブル表示、mermaid をサポートする。
  - URL だけを書いた段落は、リンク先の OGP（タイトル・説明・画像）を載せたリンクカードとして表示する。YouTube と X の投稿は oEmbed から取得する。取得できなければ通常のリンクとして表示する。
  - 本文から相対パスで参照された画像（`![](./img/a.png)` 等）を、Markdown ファイルの位置を基準に解決して表示する。`/` 始まりは開いているフォルダを基準とする。
  - 配信する画像は、開いているフォルダ配下にあり、中身がブラウザで表示できる形式（JPEG・PNG・GIF・WebP・AVIF・BMP・SVG）のファイルに限る。形式は拡張子ではなく中身から判定する。
  - Markdown ファイル間の内部リンク（`.md` を指す Markdown 記法のリンク）と、タグ（`[[タグ]]`）のメモリ内
    グラフ保持と、関連ページ表示を提供する。タグは、そのタグのページへのリンクとして扱う。
  - 本文中のリンクをクリックしたときは、そのノートのプレビューへ切り替える。Markdown のリンクの行き先は、リンク元のノートの位置を基準に解決する（`/` 始まりは開いているフォルダが基準）。
  - たどったノートは履歴として持ち、戻る・進むで行き来できる。
  - 関連ページは本文の下にカードのグリッドで並べる。リンクの向き（リンク先・リンク元）や「同じタグのノート」による欄分けはしない。
  - ノートに付いているタグごとに、「そのタグのページ（先頭）と、そのタグを持つノート」を 1 つのグループとする。グループ内のノートは、開いているノートと同じタグを多く持つものほど先に並べる（同じなら更新日時の新しい順）。
  - 開いているノートを指しているノート（リンク元）を、一番上のグループとする。開いているノートが表すタグ（ファイル名）を持つノートと、Markdown のリンクで開いているノートへリンクしているノートの両方を含む。
  - 開いているノートが Markdown のリンクでリンクしているノート（リンク先）は、最後に 1 つのグループとして本文でリンクしている順に並べる。
  - 前のグループで表示したノートは、後のグループには表示しない。1 つのグループに並べるのは 24 件までとし、超えた分は件数を示してタグの検索へ案内する。
  - 行き先がまだ存在しないもの（ページの無いタグ、行き先の無いリンク）も、行き先が無いことが分かる形で残す。
  - リンク先がまだ存在しないリンクは、本文中では赤みがかった色で示す。
- **まだ無いページ**
  - 本文のリンクや `[[タグ]]`、関連ページの「まだ無いノート」をクリックしたときは、ファイルを作らずに、そのページを詳細プレビューで開く。行き先は開いているフォルダ直下の `.md` / `.markdown` に限り、タグのページは `タグ.md` とする。
  - まだ無いページでは、本文の代わりに「md ファイルを作成する」ボタンを表示し、本文の下にはふつうのノートと同じく関連ページ（そのページを指しているノートなど）を並べる。
  - 「md ファイルを作成する」を押すと、ファイル名を見出しにした Markdown ファイルを新規作成し、拡張子に紐づいた既定のエディタで開く。同じ名前のファイルが既にあれば、上書きせずにそのまま開く。作ったファイルをウォッチャーが拾うと、開いているページは本文の表示に切り替わる。
- **本文中の画像のプレビュー**
  - Markdown プレビューの本文中の画像をクリックすると、画像ビューアを Markdown プレビューの上に重ねて開く。
  - 拡大・縮小、全体表示、原寸表示を提供する。解像度を表示する。
  - 前後の画像への移動は提供しない。画像ビューアを閉じると、元の Markdown プレビューへ戻る。

## 実装しない機能・スコープ外

- **データベース・永続化関連**
  - BuntDB のディスク永続化（AOF/RDB）は行わず、アプリ終了時にメモリは破棄する。
  - RAM の過剰消費を防ぐため、1 度のスキャンで BuntDB に展開するファイル件数に上限（既定は 2 万件。設定で 1,000〜10 万件に変えられる）を設ける。上限を超える分は自動では読み込まず、利用者が明示的に選んだときだけ続きを追加で読み込む。
- **UI・ファイル操作関連**
  - 従来の OS のような「階層型ツリー（フォルダーツリー）」は排除し、タグと検索によるフラットな閲覧に特化する。
  - ドラッグ＆ドロップによるカードの手動自由配置はサポートせず、更新順・名前順・関連度順の自動ソートのみとする（ピン留めしたノートの順番は `.taggo.json` で決める）。
  - 本文編集・タグ編集・画像加工など、既存の Markdown ファイルへの書き込みは一切行わない。
  - 複数のノートを選択してまとめて操作する機能は持たない。
  - ファイルの新規作成は、まだ無いページで「md ファイルを作成する」を押した場合と、ピン留めを保存する `.taggo.json` に限る。それ以外は利用者がエディタで作成する。
  - サブフォルダの中のノートは扱わない。
- **対応フォーマット関連**
  - 音声ファイルは扱わない。走査・検索・タグ管理・プレビューのいずれの対象にもしない。
  - 画像ファイルは走査・検索・タグ管理の対象にしない。一覧にも出さず、Markdown の本文に埋め込まれたものを表示するだけとする。
