# taggo

ローカルファイルのドキュメントとアセット（画像・音声）をタグ管理できる、Windows 専用のデスクトップアプリです。

## 概要

### コンセプト

- **フラットなタグ管理ベースのビューワ**
  - ファイルを 1 枚のサムネイル付きカードとしてフラットに並べて表示します。
  - タグとキーワードで絞り込みできます。
  - アプリ内ではフォルダの階層を見せません。
- **タグはファイル自身が持つ**
  - 各ファイル形式が標準で用意しているメタデータ領域へ書き込みます。
  - taggo は独自のデータベースを持ちません。ファイル自身のタグを唯一の正の情報として扱います。
  - taggo を使わなくなってもタグはファイルと一緒に残り、他のツールからも読めます。

### タグ編集

- Markdown・画像（jpg / png / webp）・音声（mp3 / wav / flac / ogg）のタグの読み書き
- 複数ファイルのタグの一括編集

### 検索

- 1 文字ごとに絞り込むインクリメンタル検索（タグの AND / OR / NOT、キーワードの部分一致、タグ候補の補完）
- タグバッジのクリックによる絞り込み

### 詳細プレビュー

- **Markdown プレビュー**
  - GFM・コードハイライト・mermaid、関連ページのリスト表示
  - Markdown 同士のリンクをたどる移動と、リンクする側・される側の関連ページ表示
  - 外部エディタでの変更の自動反映
- **画像プレビュー**
  - 拡大縮小、全体表示、原寸表示、マウススクロールによる前後のファイルへ移動
- **音声プレビュー**
  - 波形付きプレイヤー

### あえてしないこと

- **ファイルの中身は編集しない。** 本文の編集や画像・音声の加工はせず、触るのはタグの領域だけです。本文は好きなエディタで書き、taggo はその変更を拾います。
- **`[[WikiLink]]` を使わない。** ノート同士のリンクは普通の Markdown のリンクで書き、他のツールでもそのまま辿れるようにします。
- **標準の埋め込み場所が無い形式は扱わない。** GIF・SVG・AAC・M4A などはタグを付けられず、読み取り専用として表示します。
- **読み取り専用のファイルに無理に書かない。** 書けないときはエラーを出し、メモリ上だけ更新したように見せることはしません。

### クラウド同期フォルダを開くとき

Dropbox や OneDrive などの「オンラインのみ」のファイルは、中身を持たない置き換え用のファイルとしてローカルに置かれています。
これを普通に開くとその場でダウンロードが始まるため、同期フォルダを走査するだけで配下を丸ごとダウンロードしかねません。

taggo は、Windows のクラウドファイルの仕組み（Cloud Files API）を使う同期サービスであれば、次のように振る舞ってダウンロードを起こしません。

- フォルダ走査そのものはファイルを開きません（ディレクトリの列挙だけで済ませます）。
- 中身がクラウド上にしか無いファイルは、ファイル属性（`RECALL_ON_DATA_ACCESS` など）から見分けて**一度も開きません**。
  名前・サイズ・更新日時だけで一覧に出し、「クラウド上のみ」と表示します。
  タグは読めないのでタグ検索にはかかりませんが、ファイル名では検索できます。
- そうしたファイルにはサムネイルもプレビューも要求しません。タグの書き込みも拒否します。
- 詳細プレビューの「ダウンロードして読み込む」を押したときだけ、そのファイルを読み込みます。
- 読み込んだあとで同期サービスが「オンラインのみ」へ戻したファイルも、開く直前に属性を確かめ直して見分けます。

同期フォルダの中を選ぶと、読み込む前にサービス名（「Dropbox」など）を添えた確認を出します。

#### 対応している同期サービス

| サービス                                                                                          | 扱い                                                                       |
| ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Cloud Files API を使うもの（Dropbox・OneDrive・iCloud for Windows・Nextcloud の仮想ファイルなど） | 対応。クラウド上にだけあるファイルを見分けて開きません                     |
| Google ドライブの「ストリーミング」（既定では G: の仮想ドライブ）                                 | 対象外。自動で判定し、読み込みを断ります                                   |
| Google ドライブの「ミラーリング」など、全ファイルを常にローカルに置く設定                         | 対応。ダウンロードの問題が起きないので、ふつうのフォルダとして読み込みます |

Google ドライブのストリーミングは Cloud Files API を使わず、クラウド上にしか無いファイルも通常のファイルに見えるため、見分けられません。
ファイルシステムが FAT32 でラベルが「Google Drive」のボリュームを、このドライブと判定しています。

## タグ埋め込み方式

### Markdown

ドキュメントは Markdown 形式で、Front Matter（YAML）形式をサポートしています。

```markdown
---
tags:
  - golang
  - 開発メモ
---

# ここから本文
```

### 画像ファイル

- 画像ファイルは .jpg, .png, .webp 形式です。
- Exif.Image.XPKeywords や XMP:Subject などの標準タグ領域に書き込みます。

### 音声ファイル

- 音声ファイルは .mp3, .wav, .flac, .ogg 形式です。
- .mp3 は ID3v2 タグ（Genre や Comment、Keywords 欄）にタグ文字列を書き込みます。
- .wav は INFO chunk や ID3 chunk に埋め込みます。
- .flac と .ogg は Vorbis Comment の KEYWORDS 欄に書き込みます。

## 対応状況

| 種別     | 拡張子            | 読み取り | 書き込み | 保存先                                                             |
| -------- | ----------------- | -------- | -------- | ------------------------------------------------------------------ |
| Markdown | `.md` `.markdown` | ✓        | ✓        | YAML Front Matter の `tags`                                        |
| 画像     | `.jpg` `.jpeg`    | ✓        | ✓        | Exif IFD0 の `XPKeywords`（読み取りは XMP `dc:subject` も併用）    |
| 画像     | `.png`            | ✓        | ✓        | eXIf チャンクの `XPKeywords`（読み取りは `tEXt` / `iTXt` も併用）  |
| 画像     | `.webp`           | ✓        | ✓        | `XMP ` チャンクの `dc:subject`（読み取りは `EXIF` チャンクも併用） |
| 音声     | `.mp3`            | ✓        | ✓        | ID3v2 の `TXXX:KEYWORDS`                                           |
| 音声     | `.flac`           | ✓        | ✓        | Vorbis Comment の `KEYWORDS`                                       |
| 音声     | `.wav`            | ✓        | ✓        | RIFF `LIST/INFO` の `IKEY`（読み取りは `id3 ` チャンクも併用）     |
| 音声     | `.ogg`            | ✓        | ✓        | Vorbis Comment の `KEYWORDS`（中身は Vorbis / Opus）               |

- 書き込みは一時ファイルへ出力してから rename する方式で、途中で失敗しても元のファイルを壊しません。
- 読み取り専用のファイルはエラーとして表示し、メモリ上だけ更新するような不整合は起こしません。
- 判定はできても taggo が扱えない形式（AVIF・HEIC・BMP・TIFF・GIF・SVG・M4A）は、読み取り専用として理由を添えて表示します。正しい MIME タイプで配信するため、ブラウザが対応している形式（GIF・SVG・AVIF など）はプレビューできます。
- GIF・SVG・AAC・M4A はタグの標準的な埋め込み場所を持たないため、対応フォーマットから外しています。

## 使い方

- **検索バー**（最上部）: 起動時にフォーカスが当たり、1 文字入力するごとに絞り込みが走ります。
  - `#タグ` … そのタグを持つものだけ（完全一致）
  - `-#タグ` … そのタグを持たないものだけ
  - `#a OR #b` … どちらかのタグを持つもの
  - `語` … タイトル・ファイル名・本文抜粋・タグへの部分一致
  - `"複数 語"` … 空白を含めて 1 語として扱う
  - `#` を入力すると、登録済みタグの候補が使用件数の多い順に出ます。
- **カード**: クリックで詳細プレビュー、`Ctrl` を押しながらクリック（またはカード左上のチェック）で複数選択。
  カード下部の `#タグ` バッジをクリックすると、そのタグが検索バーに足されて即座に絞り込まれます。
- **一括編集**: 複数選択するとツールバーに「タグを一括編集」が出ます。追加と削除を別々に指定できます。
- **2 万件を超えるフォルダ**: 1 回に読み込むのはパス順の先頭 2 万件までです。残りがあるとバナーとツールバーに件数が出るので、
  「続きを読み込む」で 2 万件ずつ、「すべて読み込む」で残り全部を追加できます。読み込んでいないファイルは検索の対象外なので、
  絞り込み中は画面の下端にその件数が出ます。
- **関連ページ**: Markdown のプレビューは、関連ページがあると本文の右に 2 カラムで並びます。
  上段が「このページからリンク」、下段が「このページへのリンク」で、カードをクリックすると
  そのノートへ移ります。まだ書いていないノートへのリンクは「まだ無いノート」として点線で出ます。
  カードの行き先が今の絞り込みから外れているときは、検索条件のほうを切り替えます。
