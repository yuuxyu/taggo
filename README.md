# taggo

Markdown を使った、タグ管理のローカル Wiki デスクトップアプリです（Windows 専用）。
好きなエディタで書いた Markdown のフォルダを開くと、タグとリンクでたどれる Wiki として読めます。

## 概要

### コンセプト

- **Markdown のノートだけを扱うローカル Wiki**
  - フォルダ配下の Markdown を、1 枚ずつのカードとしてフラットに並べて表示します。
  - タグとキーワードで絞り込み、ノート同士のリンクと関連ページでたどれます。
  - アプリ内ではフォルダの階層を見せません。
- **タグはノート自身が持つ**
  - タグは Markdown の Front Matter（YAML）へ書き込みます。
  - taggo は独自のデータベースを持ちません。ノート自身のタグを唯一の正の情報として扱います。
  - taggo を使わなくなってもタグはノートと一緒に残り、他のツールからも読めます。

### タグ編集

- Markdown の Front Matter のタグの読み書き
- 複数ノートのタグの一括編集

### 検索

- 1 文字ごとに絞り込むインクリメンタル検索（タグの AND / OR / NOT、キーワードの部分一致、タグ候補の補完）
- タグバッジのクリックによる絞り込み

### 詳細プレビュー

- **Markdown プレビュー**
  - GFM・コードハイライト・mermaid、関連ページのリスト表示
  - Markdown 同士のリンクをたどる移動と、リンクする側・される側の関連ページ表示
  - 拡張子に紐づいたエディタで開くボタン（保存した変更は自動で反映）
  - 外部エディタでの変更の自動反映
  - タグそのものを説明するタグページ（`tag:` を宣言した Markdown）
  - URL だけを書いた段落のリンクカード表示（YouTube・X にも対応）
  - 本文に埋め込んだ画像の表示
- **画像ビューア**
  - 本文中の画像をクリックすると開きます。拡大縮小、全体表示、原寸表示
  - 閉じると元の Markdown プレビューへ戻ります（前後の画像への移動はありません）

### あえてしないこと

- **ノートの本文は編集しない。** 本文の編集や画像の加工はせず、触るのは Front Matter のタグだけです。本文は好きなエディタで書き、taggo はその変更を拾います。
- **`[[WikiLink]]` を使わない。** ノート同士のリンクは普通の Markdown のリンクで書き、他のツールでもそのまま辿れるようにします。
- **画像と音声をタグ管理しない。** 画像は本文から参照されたものを表示するだけで、一覧にも検索にも出しません。音声は読み込みません。
- **タグページを taggo から作らない。** タグページもふつうの Markdown なので、好きなエディタで書いて置けば認識します。
- **読み取り専用のファイルに無理に書かない。** 書けないときはエラーを出し、メモリ上だけ更新したように見せることはしません。

### クラウド同期フォルダを開くとき

Dropbox や OneDrive などの「オンラインのみ」のファイルは、中身を持たない置き換え用のファイルとしてローカルに置かれています。
これを普通に開くとその場でダウンロードが始まるため、同期フォルダを走査するだけで配下を丸ごとダウンロードしかねません。

taggo は、Windows のクラウドファイルの仕組み（Cloud Files API）を使う同期サービスであれば、次のように振る舞ってダウンロードを起こしません。

- フォルダ走査そのものはファイルを開きません（ディレクトリの列挙だけで済ませます）。
- 中身がクラウド上にしか無いファイルは、ファイル属性（`RECALL_ON_DATA_ACCESS` など）から見分けて**一度も開きません**。名前・サイズ・更新日時だけで一覧に出し、「クラウド上のみ」と表示します。タグは読めないのでタグ検索にはかかりませんが、ファイル名では検索できます。
- そうしたファイルにはプレビューを要求しません。タグの書き込みも拒否します。
- 本文に埋め込んだ画像の中身がクラウド上にしか無いときは、その画像を表示しません。ノートを開いただけでダウンロードが始まらないようにするためです。
- 詳細プレビューの「ダウンロードして読み込む」を押したときだけ、そのファイルを読み込みます。
- 読み込んだあとで同期サービスが「オンラインのみ」へ戻したファイルも、開く直前に属性を確かめ直して見分けます。

### リンクカードの通信

Markdown の本文に URL だけを 1 行で書くと、プレビューではリンク先のタイトル・説明・画像を載せたカードになります。

```markdown
https://www.youtube.com/watch?v=xxxxxxxxxxx
```

- 文中のリンクや、`[名前](https://…)` のように表示名を付けたリンクはカードにしません。
- ノートを開いた時点でリンク先へ通信します。接続するのは本文に書かれた URL（と YouTube・X の oEmbed）だけです。
- 一般のページは OGP を、YouTube と X（投稿の URL）はそれぞれの oEmbed を読みます。X の投稿は画像を出さず、本文だけを表示します。
- ローカルネットワーク（`localhost` や `192.168.*` など）を指す URL には接続しません。取得できなかった URL は、ただのリンクとして表示します。
- 取得した内容はアプリを閉じるまでメモリに覚えておき（失敗は 5 分、成功は 1 時間）、同じ URL へ何度も通信しません。

#### 対応している同期サービス

| サービス                                                                                          | 扱い                                                                       |
| ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Cloud Files API を使うもの（Dropbox・OneDrive・iCloud for Windows・Nextcloud の仮想ファイルなど） | 対応。クラウド上にだけあるファイルを見分けて開きません                     |
| Google ドライブの「ストリーミング」（既定では G: の仮想ドライブ）                                 | 対象外。自動で判定し、読み込みを断ります                                   |
| Google ドライブの「ミラーリング」など、全ファイルを常にローカルに置く設定                         | 対応。ダウンロードの問題が起きないので、ふつうのフォルダとして読み込みます |

Google ドライブのストリーミングは Cloud Files API を使わず、クラウド上にしか無いファイルも通常のファイルに見えるため、見分けられません。
ファイルシステムが FAT32 でラベルが「Google Drive」のボリュームを、このドライブと判定しています。

## タグ埋め込み方式

### Markdown

ノートは Markdown 形式（`.md` / `.markdown`）で、Front Matter（YAML）形式をサポートしています。

```markdown
---
tags:
  - golang
  - 開発メモ
---

# ここから本文
```

- 読み取りでは `keywords:` も `tags:` の別名として受け付けます。書き込むときは `tags:` にまとめます。
- 書き込みは一時ファイルへ出力してから rename する方式で、途中で失敗しても元のファイルを壊しません。
- 読み取り専用のファイルはエラーとして表示し、メモリ上だけ更新するような不整合は起こしません。

#### タグページ

Front Matter に `tag:` を書いた Markdown は、そのタグを説明する「タグページ」になります。
`tags:`（そのノート自身に付けるタグ）とは別のキーなので、タグページ自身にも好きなタグを付けられます。

```markdown
---
tag: golang
tags:
  - プログラミング
---

# Go

Go 言語に関するメモの入口。書き方の方針は [コーディング規約](./go-style.md) を参照。
```

- `tag:` に書けるタグは 1 つだけです。リストで複数書いたものはタグページとみなしません。
- ファイル名や置き場所は問いません。他のツールで開いても、ただのメタデータとして読めます。
- 同じタグを複数のファイルが宣言していると、警告を出したうえで全部を表示します。どれか 1 つに絞ってください。

### 本文に埋め込む画像

```markdown
![構成図](./images/architecture.png)
```

- 相対パスは Markdown ファイルの位置を基準に、`/` 始まりは開いているフォルダを基準に解決します。
- 表示できるのは、開いているフォルダ配下にある JPEG・PNG・GIF・WebP・AVIF・BMP・SVG です。形式は拡張子ではなく中身から判定します。
- 画像は一覧にも検索にも出ず、タグも付けません。`.attachments` のような隠しフォルダに置いた画像も表示できます。

## 使い方

- **検索バー**（最上部）: 起動時にフォーカスが当たり、1 文字入力するごとに絞り込みが走ります。
  - `#タグ` … そのタグを持つものだけ（完全一致）
  - `-#タグ` … そのタグを持たないものだけ
  - `#a OR #b` … どちらかのタグを持つもの
  - `語` … タイトル・ファイル名・本文抜粋・タグへの部分一致
  - `"複数 語"` … 空白を含めて 1 語として扱う
  - `#` を入力すると、登録済みタグの候補が使用件数の多い順に出ます。
- **カード**: クリックでノートの詳細プレビュー、`Ctrl` を押しながらクリック（またはカード左上のチェック）で複数選択。
  カード下部の `#タグ` バッジをクリックすると、そのタグが検索バーに足されて即座に絞り込まれます。
- **タグページ**: `#タグ` で検索すると、そのタグのタグページがグリッドの上に見出しとして出ます（一覧のカードには混ざりません）。見出しをクリックすると本文が開きます。右の列の関連ページは、ふつうのノートと同じくリンクと同じタグのノートです。タイトルの下の「#タグ のタグページ」をクリックすると、そのタグの絞り込みに切り替わります。タグで検索していないときは、タグページもふつうのカードとして一覧に出て、「タグページ」の印が付きます。
- **一括編集**: 複数選択するとツールバーに「タグを一括編集」が出ます。追加と削除を別々に指定できます。
- **本文中の画像**: クリックすると画像ビューアが開きます。`Esc`・「閉じる」・マウスの戻るボタンで Markdown プレビューへ戻ります。
- **2 万件を超えるフォルダ**: 1 回に読み込むのは Markdown のパス順の先頭 2 万件までです。残りがあるとバナーとツールバーに件数が出るので、「続きを読み込む」で 2 万件ずつ、「すべて読み込む」で残り全部を追加できます。読み込んでいないファイルは検索の対象外なので、絞り込み中は画面の下端にその件数が出ます。
- **関連ページ**: Markdown のプレビューは、関連ページがあると本文の右に 2 カラムで並びます。上段が「このページからリンク」、下段が「このページへのリンク」で、カードをクリックするとそのノートへ移ります。まだ書いていないノートへのリンクは「まだ無いノート」として点線で出ます。カードの行き先が今の絞り込みから外れているときは、検索条件のほうを切り替えます。
