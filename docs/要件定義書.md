# taggo 要件定義書

## システム概要・アーキテクチャ方針

- **コンセプト**
  - Markdown を使った、タグ管理のローカル Wiki デスクトップアプリとする。ノートはアプリの中で書き、テキストエディタと見た目を分けない（書いたその場で整えて見せる）。
  - 一覧・検索・タグ管理の対象は、開いたフォルダの直下にある Markdown のノートだけとする。サブフォルダの中は読まない。画像は Markdown の本文に埋め込んで表示するためだけに扱い、音声は扱わない。
  - ノートのファイル名（拡張子を除く）が、そのままタグを表す。`golang.md` は `golang` タグのページとする。
- **対応環境**
  - Windows 専用とする。動作を確かめられるのが Windows だけのため、ほかの OS には対応しない。
  - クラウド同期サービスは Dropbox で動作を確かめる。
- **メタデータ保持方針**
  - ノートに付くタグは、本文の `[[タグ]]` を正（Single Source of Truth）として扱う。Front Matter は使わない。
  - ノートの本文は、編集画面で利用者が書いた内容をそのまま保存する。タグの付け外しも、本文の `[[タグ]]` を書き換えて行う。taggo が本文を勝手に整形し直すことはない。
  - 利用者が書いたもの以外でノートを書き換えるのは、ページの名前を変えたときに、そのページを指す参照（`[[タグ]]` と Markdown のリンク）を、フォルダ直下のすべてのノートで書き換える場合だけとする（後述）。
- **データベース・検索方針**
  - Pure Go 製の完全インメモリ KV ストア「BuntDB」を採用する。
  - ディスクへのデータベース永続化（.db ファイル保存）は行わない。
  - アプリ起動時およびフォルダ選択時にフォルダ直下の Markdown を走査し、BuntDB へデータを展開して高速なメモリ内検索を提供する。
- **設定の保存方針**
  - アプリの好み（起動時に開くフォルダ、一覧の既定の並び順、1 回の走査の上限件数、テーマ）に限り、`%APPDATA%\taggo\settings.json` へ保存する。
  - 保存してよいのは「消えても初期状態へ戻るだけ」のものに限る。タグ・走査結果・キャッシュなど、ノートから導けるものやノートの中身の写しは保存しない。
  - 設定を一度も変えなければ、設定ファイルは作らない。前回開いたフォルダは、起動時に「前回開いたフォルダ」を開く設定にしたときだけ記録する。
  - 設定ファイルが壊れていても既定の設定で起動し、壊れたファイルは上書きせずに退避する。
  - 例外として、一覧のピン留めは、開いたフォルダの直下の `.taggo.json` に保存する。そのフォルダの Wiki の見せ方なので、ノートと一緒に同期・バックアップされるようにするため。taggo の知らない項目は書き込むときも残し、JSON として壊れていれば書き換えない。
- **クラウド同期フォルダと通信の方針**
  - Dropbox などのクラウド同期フォルダでは、開いたフォルダの直下の Markdown と、本文が参照している画像は、読む時点で同期サービスにダウンロードさせてよい。ノートをアプリの中で編集するため、フォルダ直下のノートはすべて手元にあるものとして扱う。
    - フォルダを開いたときの走査で、フォルダ直下の Markdown をすべて読む（中身がクラウド上にしか無いノートは、この時点でダウンロードされる）。「クラウド上のみ」のノートを読まずに一覧へ出す扱いはしない。
    - 本文の画像は、表示するときに読む（中身がクラウド上にしか無ければ、この時点でダウンロードされる）。
    - フォルダ直下の `.taggo.json` も、ノートと同じく読む。
    - サブフォルダの中や、本文が参照していないファイルは読まない。読み込みの上限を超えた分も、利用者が続きを読み込むまでは読まない。
  - 例外として、Markdown 本文に URL だけを書いた行は、ノートを開いた時点でリンク先からリンクカードの内容を取得する。本文の外部画像と同じく、利用者が本文に書いた URL だけを対象とし、ローカルネットワークのアドレスには接続しない。
  - 例外として、カードのサムネイルが外部 URL の画像か YouTube 動画のときは、一覧を表示した時点でその画像を読み込む。接続先は本文に書かれた画像の URL と、YouTube のサムネイル画像（`i.ytimg.com`）だけとする。
- **UI・デザイン方針**
  - 「最上部検索バー ＋ カード型グリッド（カード内にタグバッジ配置）」をメイン画面とする。
  - アプリ内ではフォルダのような階層構造を持たせず、ノートを最小粒度としたフラット管理をベースとする。フォルダ直下だけを読むので、同じ名前（同じタグ）のノートがフォルダ違いで並ぶことはない。
  - ノート同士のリンク関係で検索、可視化できるようにする。
  - スタイルは Tailwind CSS のユーティリティで組み立て、独自の CSS は配色トークンと要素の既定値に限る。アイコンは Heroicons を用い、配色は既定では OS のテーマ設定に追従させ、設定でライト・ダークに固定できるようにする。

## 画面要件

- **検索バー（最上部固定）**
  - アプリ起動時に検索バーへ自動でフォーカス（キャレット配置）を当てる。
  - 1 文字入力ごとに追従するリアルタイム（インクリメンタル）検索を提供する。
  - 検索は単純な全文検索とする。空白で区切った語をすべて含むノートを結果とし、語はタイトル・ファイル名・本文の抜粋・タグから大文字小文字を区別せずに探す。タグを指定する記法（`#タグ`）や、AND / OR / NOT のような条件式は持たない。
  - 入力全体がタグの名前と一致するときは、そのタグのページ（ファイル名がそのタグのノート）を並び順にかかわらず結果の先頭に出す。
  - 入力全体と同じ名前のタグのページがまだ無いときは、結果の上に「`タグ.md` を作成する」ボタンを表示する。押すと、まだ無いページの「md ファイルを作成する」と同じくファイルを作り、そのページを編集画面で開く。ファイル名にできない入力では表示しない。
    - ボタンが出ている間は、検索バーで Enter を押しても作る（日本語入力の変換を確定する Enter では作らない）。入力したばかりで結果が追いついていないときは、前の検索語のページを作らないよう何もしない。ボタンが出ていないとき（そのタグのページが既にあるときなど）の Enter は何もしない。
- **カード型ビジュアルグリッド**
  - 走査された全ノートを「カード」としてグリッド表示する。
  - 検索していないときは、ピン留めしたノートをピン留めした順に先頭へ並べ、残りのカードは次の行から並べる。検索中はピン留めを先頭にしない（検索語と同じ名前のタグのページを先頭の別枠とする）。
  - カードには見出しと本文冒頭の抜粋、タグだけを表示する。拡張子やファイルサイズは表示しない。
  - 本文で画像か YouTube 動画を使っているノートは、抜粋の代わりに、本文で最初に現れる画像または動画のサムネイルを表示する。画像を読み込めないときは抜粋に戻す。
  - 各カードの下部に、ノートのタグ（本文の `[[タグ]]`）をバッジ（`#tag`）として一覧表示する。4 行に収まらないタグは「+N」と数で示し、タグ欄に乗ったときに全部を重ねて表示する。
- **インタラクション＆操作性**
  - カード上の「#タグバッジ」をクリックすると、そのタグで検索する（そのタグのページが先頭に、タグを付けたノートがその後ろに並ぶ）。
  - カードとノートの画面から、ノートを一覧の先頭にピン留めし、また外せる。
  - カードをクリックすると、画面遷移なしでノートの編集画面を開く。
  - 大量ノート描画時の遅延を防ぐため、仮想スクロール（Virtual Scroll）を採用する。

## コア機能要件（In-Scope）

### タグ管理

- **タグの付け方**
  - ノートの本文に `[[タグ]]` と書いたものだけをタグとする。コードブロックとインラインコードの中の `[[ ]]` はタグとして読まない。
  - Front Matter（先頭の `---` で囲んだ YAML）は使わない。`tags:` や `title:` を書いても、タグや見出しにはならない。ほかのツールで書いたノートに Front Matter があれば、抜粋と文字数からは外し、編集画面では薄く小さく表示する（中身は読まず、書き換えもしない）。
  - タグの付け外しは、編集画面で本文の `[[タグ]]` を書き換えて行う。タグだけを編集する専用の画面は持たない。
- **タグのページ**
  - ノートのファイル名（拡張子を除く）が、そのタグを表すページとなる。タグとファイル名の突き合わせでは、大文字小文字と空白の連なりを区別しない。
  - 本文の `[[タグ]]` は、編集画面でそのタグのページへのリンクとして表示する。ページがまだ無ければ赤みがかった色で示し、クリックすると「まだ無いページ」として開く（後述）。
  - Windows のファイル名に使えない文字を含むタグには、ページを作らない。
- **ピン留め**
  - ノートを一覧の先頭にピン留めできる。ピン留めは開いたフォルダ直下の `.taggo.json` にファイル名の並びとして保存し、外で書き換えられたときも読み直す。
- **ページの名前の変更**
  - ノートの画面の「名前を変更」で、ページのファイル名（拡張子を除く部分。拡張子は変えない）を変えられる。まだ無いページの名前は変えられない。
  - 名前を変えると、フォルダ直下のすべてのノート（読み込みの上限で一覧に載っていないノートも含む）で、そのページを指す参照を新しい名前に書き換える。
    - `[[変更前の名前]]`。タグの突き合わせと同じく、大文字小文字と空白の連なりは区別しない。
    - そのページへの Markdown のリンクの行き先。書き換えるのはファイル名の部分だけで、フォルダの部分・拡張子・`#` 以降は書かれたまま残す。もとのファイル名が `%` で書き表されていれば、新しい名前も同じように書き表す。
    - そのリンクの表示文字が、変更前の名前か拡張子付きのファイル名と同じなら、その表示文字。
    - 名前を変えるページ自身の最初の見出しが、変更前の名前と同じなら、その見出し。
    - コードブロック・インラインコード・先頭の `---` で囲んだブロックの中は書き換えない。本文中のふつうの文字列も書き換えない。
  - 書き換える前に、書き換わるノートと、大きすぎて書き換えないノートを確認ダイアログで示す。名前を変える前に、編集画面の書きかけを保存しておく。
  - 先にすべてのノートを読み、読めないノートがあれば何も変えずに断る。同じ名前のページが既にあるとき、ファイル名に使えない文字や `[` `]` を含む名前のときも断る。大文字小文字だけの変更はできる。
  - ノートの書き換えは、同じフォルダの一時ファイルに書いてから置き換える。
  - ピン留めしていたページは、`.taggo.json` のファイル名も付け替える。
  - 名前を変えたページを開いていれば、そのまま新しい名前のページとして開いておき、移動の履歴も新しい名前へ付け替える。
- **BuntDB によるインメモリタグ抽出＆検索**
  - 指定ルート直下の Markdown を非同期スキャンし、BuntDB へデータ投入する（Key: ファイルパス, Value: メタデータ JSON）。
  - BuntDB のカスタムインデックスを利用し、全文検索および更新日時順・名前順のソートを提供する。
  - File Watcher による変更検知時、BuntDB 上の該当レコードを自動で同期更新・削除する。

### 編集機能

- **常に編集できる画面**
  - ノートを開くと、そのまま本文を編集できる。閲覧と編集のモードは分けない。
  - ファイルの中身は書いたままの Markdown とし、見た目だけを整えて見せる（ライブプレビュー）。見出しは大きく、太字は太く、リンクと `[[タグ]]` はリンクの色で表示し、`##` や `**` のような記号は隠す。
  - カーソルのある行（リンク・強調・`[[タグ]]` はその要素）だけは記号を表示し、そのまま書き直せるようにする。編集画面からフォーカスが外れている間は、すべての記号を隠す。
  - 表と mermaid のコードブロックと、URL だけを書いた行（リンクカード）は、カーソルが外れている間は描いた結果に行ごと置き換えて表示する。上下キーでその行に入るか、クリックすると（リンクカードはカードの外側）、元の記述に戻って書き直せる。
  - 画像の記述は画像として、`- [ ]` / `- [x]` はチェックボックスとして表示する。チェックボックスのクリックで本文の印を書き換える。
  - 記号を隠しているリンクと `[[タグ]]` はクリックで、記号を表示しているものは Ctrl を押しながらのクリックで行き先を開く。
- **入力補完**
  - 行の頭で `#` から `######` に続けて空白を打つと、その場でその大きさの見出しの見た目になる。
  - `[[` と打つと閉じの `]]` を補い、使われているタグとページのあるタグを、使われている件数の多い順に候補として出す。選ぶとタグを入れて `]]` の後ろへ進む。候補に無いタグはそのまま打てばよい。コードの中では出さない。
  - 行の頭で ``` と打つとコードブロックの言語名を候補に出し、Enter で閉じの ``` を補って間の行にカーソルを置く。閉じのフェンスが既にあるときは補わない。
  - `**` と打つと閉じの `**` を補い、間にカーソルを置く。閉じの `**` の手前で `*` を打つと、補った記号の上を進む。文字を選んで `*` を打つと、選んだ文字を囲む。Ctrl + I で、選んだ文字を斜体にする（もう一度押すと戻す）。太字のキー（Ctrl + B）はカーソル移動に使うので持たない。
  - 括弧（`(` `[` `{`）は閉じの括弧を補う。箇条書き・番号付きリスト・引用の行で Enter を押すと、次の行に同じ記号を補う。
- **キー操作**
  - Emacs 風のキーでカーソルを動かす。Shift を足すと、動いた先までを選ぶ。
    - Ctrl + A / Ctrl + E … 行頭 / 行末。動く先は改行で区切られた 1 行の端で、折り返して見えている行の端ではない。
    - Ctrl + P / Ctrl + N … 上の行 / 下の行。上下キーと同じく、描いた結果に置き換えている行（表・図・リンクカード）にも入れる。
    - Ctrl + B / Ctrl + F … 1 文字左 / 1 文字右。
  - Ctrl + H は Backspace と同じに消す（補った括弧の対や、箇条書き・引用の記号の消し方も Backspace と同じ）。
  - Ctrl + M は Enter と同じに改行する（閉じのフェンスや、箇条書き・引用の記号の補いも Enter と同じ）。補完の候補を決める働きは持たない。
  - Ctrl + O は、カーソルのある `[[タグ]]` ならそのタグのページを、リンクや URL ならその行き先を開く（クリックでたどるのと同じ）。カーソルが要素の左右どちらに接していてもよい。何も無ければ何もしない。
  - 編集画面にカーソルが無いとき（一覧から開いた直後など）に Enter・Ctrl + M・Ctrl + N を押すと、本文の先頭にカーソルを置く。ほかの画面（画像ビューア・ダイアログ・履歴の一覧）が重なっているときは、そちらの働きを優先する。Enter と Ctrl + M は、ノートの画面のボタンなどにフォーカスがあるときもそちらを優先する（Ctrl + N はボタンの働きとぶつからないので本文へ移す）。
  - ノートの画面を開いたら、フォーカスをその画面の中へ移す。後ろの一覧（カードなど）がキー操作を受けないようにするため。
  - 入力補完の候補が出ている間は、Ctrl + N / Ctrl + P で候補を選ぶ。
  - これらのキーの既定の働き（Ctrl + A のすべて選択、WebView の Ctrl + P の印刷・Ctrl + N の新しいウィンドウなど）は、編集画面では使わない。
- **画像の貼り付け**
  - 編集画面に画像を貼り付ける（またはドロップする）と、開いているフォルダの直下に保存し、カーソルの位置（ドロップならその位置）に `![](名前)` を入れる。
  - 名前は保存した日時（`20261011-153000.png`）とし、同じ名前のファイルがあれば `-2` `-3` … を付ける。拡張子は中身の形式から決める。表示できる形式（JPEG・PNG・GIF・WebP・AVIF・BMP・SVG）の画像だけを保存し、32 MB を超えるものは保存しない。
  - 貼り付けた中身に文字があれば、画像ではなく文字として貼る。
- **保存**
  - 入力が止まって 1 秒経ったら自動で保存する。ほかのノートへ移るとき、編集画面からフォーカスが外れたとき、ウィンドウを閉じるとき、名前を変える前にも、待たずに保存する。
  - 保存は同じフォルダの一時ファイルに書いてから置き換える。元のファイルの改行（LF / CRLF）と先頭の BOM は保つ。中身が変わっていなければ書き込まない。
  - ほかのアプリ（同期サービス・ウイルス対策ソフトなど）や taggo 自身がファイルを読んでいる最中でも、保存を失敗させない。taggo 自身の読み込みは置き換えを邪魔しない開き方にし、ほかのアプリが使用中なら少し（最大 2 秒ほど）待って置き換え直す。それでも保存できなければ一度だけ知らせ、少し後に自動でもう一度保存する。
  - 保存する前に、読んだときからファイルがほかのアプリで書き換えられていないかを確かめる。書き換えられていれば保存せず、「ほかでの変更を読み込む」か「この内容で上書き」かを選んでもらう。選ぶまで自動では保存しない。
  - 書きかけが無いときにほかのアプリで書き換えられたら、その内容を編集画面へ読み込む。
  - 8 MB を超えるノートは開かない（保存もしない）。

### 表示機能

- **Markdown の表示**
  - CommonMark / GFM (GitHub Flavored Markdown) 規格に準拠して表示する。
  - ノートのタグ（本文の `[[タグ]]`）を、ヘッダーに「タグバッジ」として表示する。
  - フッターに本文の文字数（Front Matter と改行を除き、見た目の 1 文字ごとに数える）を表示し、編集に合わせて数え直す。一覧の並びで前後のノートへ移る機能は持たない。
  - コードブロックの色分け（言語名に合わせる）、テーブル表示、mermaid をサポートする。
  - URL だけを書いた行は、カーソルが外れている間、リンク先の OGP（タイトル・説明・画像）を載せたリンクカードとして表示する。YouTube と X の投稿は oEmbed から取得する。取得できなければ通常のリンクとして表示する。
    - 前後を空行で区切らなくてよい。URL を続けて書いた行や、すぐ次の行に文を書いた URL の行もカードにする（Markdown としては 1 つの段落でも、taggo の中では行ごとに見る）。
    - カードは URL の行と置き換え、URL のための行を別に取らない。
    - 文中のリンク、`[名前](https://…)` のように表示名を付けたリンク、箇条書きや引用の中の URL はカードにしない。
    - `<…>` で囲まずに書いた URL の末尾の `_` と `~` は、URL に含める（GFM は含めないが、`https://x.com/name_` のように末尾が `_` の URL を落とすと別のページになるため）。強調や取り消し線の記号のときと、後ろに空白か行末以外が続くときは含めない。文中のリンクの行き先も同じ規則で決める。
  - 本文から相対パスで参照された画像（`![](./img/a.png)` 等）を、Markdown ファイルの位置を基準に解決して表示する。`/` 始まりは開いているフォルダを基準とする。
  - 配信する画像は、開いているフォルダ配下にあり、中身がブラウザで表示できる形式（JPEG・PNG・GIF・WebP・AVIF・BMP・SVG）のファイルに限る。形式は拡張子ではなく中身から判定する。
  - Markdown ファイル間の内部リンク（`.md` を指す Markdown 記法のリンク）と、タグ（`[[タグ]]`）のメモリ内
    グラフ保持と、関連ページ表示を提供する。タグは、そのタグのページへのリンクとして扱う。
  - 本文中のノートへのリンクをたどったときは、そのノートの編集画面へ切り替える。Markdown のリンクの行き先は、リンク元のノートの位置を基準に解決する（`/` 始まりは開いているフォルダが基準）。
  - 見てきた一覧（検索結果）とノートは 1 本の履歴として持ち、一覧でもノートの画面でも戻る・進むで行き来できる。
    - 戻る・進むは、画面の「←」「→」のほか、Alt + ← / →、Ctrl + [ / Ctrl + ]、マウスの戻る／進むボタンで行う。入力欄や編集画面の中でも効かせる（編集画面では Ctrl + [ / ] の既定の字下げは使わない）。キーの [ と ] は、キーボードの配列にかかわらず入力される文字で見分ける。
    - 履歴に積むのは、カードやリンクから開いたノートと、タグのクリックで始めた検索の一覧。検索バーへの入力は 1 文字ごとに積まず、今の一覧の検索語を書き換える。
    - 履歴の先頭は必ず一覧とし、ノートからは「戻る」で開く前の一覧へ戻れる。ノートの画面を閉じる専用のボタンは置かない（`Esc` で手前の一覧へ戻る。入力補完の候補を出している間の `Esc` は候補を閉じるだけ）。
  - 関連ページは本文の下にカードのグリッドで並べる。リンクの向き（リンク先・リンク元）や「同じタグのノート」による欄分けはしない。
  - ノートに付いているタグごとに、「そのタグのページ（先頭）と、そのタグを持つノート」を 1 つのグループとする。グループ内のノートは、開いているノートと同じタグを多く持つものほど先に並べる（同じなら更新日時の新しい順）。
  - 開いているノートを指しているノート（リンク元）を、一番上のグループとする。開いているノートが表すタグ（ファイル名）を持つノートと、Markdown のリンクで開いているノートへリンクしているノートの両方を含む。
  - 開いているノートが Markdown のリンクでリンクしているノート（リンク先）は、最後に 1 つのグループとして本文でリンクしている順に並べる。
  - 前のグループで表示したノートは、後のグループには表示しない。1 つのグループに並べるのは 24 件までとし、超えた分は件数を示してタグの検索へ案内する。
  - 行き先がまだ存在しないもの（ページの無いタグ、行き先の無いリンク）も、行き先が無いことが分かる形で残す。
  - リンク先がまだ存在しないリンクは、本文中では赤みがかった色で示す。
  - 本文中では、アプリの中でたどるリンク（`[[タグ]]` とノートへのリンク）と、既定のブラウザで開く外部リンクを見た目で区別する。前者は下線を付けず（ホバー時のみ下線）、後者は下線と末尾の「↗」で示す。
- **まだ無いページ**
  - 本文のリンクや `[[タグ]]`、関連ページの「まだ無いノート」をクリックしたときは、ファイルを作らずに、そのページをノートの画面で開く。行き先は開いているフォルダ直下の `.md` / `.markdown` に限り、タグのページは `タグ.md` とする。
  - まだ無いページでは、本文の代わりに「md ファイルを作成する」ボタンを表示し、本文の下にはふつうのノートと同じく関連ページ（そのページを指しているノートなど）を並べる。
  - 「md ファイルを作成する」を押すと、ファイル名を見出しにした Markdown ファイルを新規作成してすぐに一覧へ載せ、開いているページを編集画面に切り替えて、見出しの下の行（見出しとの間は 1 行空ける）にカーソルを置く。外部のエディタを使わずに、そのまま書き始められる。同じ名前のファイルが既にあれば、上書きせずにそのページを開く。
- **外部エディタ**
  - ノートを外部のエディタで開く機能は持たない。書くのは taggo の編集画面で足りるため。
  - ほかのアプリ（別の PC からの同期を含む）でノートが書き換えられたときは、ウォッチャーが拾って編集画面へ反映する（保存の項を参照）。
- **本文中の画像のビューア**
  - 編集画面の本文中の画像をクリックすると、画像ビューアを編集画面の上に重ねて開く。
  - 拡大・縮小、全体表示、原寸表示を提供する。解像度を表示する。
  - 前後の画像への移動は提供しない。画像ビューアを閉じると、元の編集画面へ戻る。

## 実装しない機能・スコープ外

- **データベース・永続化関連**
  - BuntDB のディスク永続化（AOF/RDB）は行わず、アプリ終了時にメモリは破棄する。
  - RAM の過剰消費を防ぐため、1 度のスキャンで BuntDB に展開するファイル件数に上限（既定は 2 万件。設定で 1,000〜10 万件に変えられる）を設ける。上限を超える分は自動では読み込まず、利用者が明示的に選んだときだけ続きを追加で読み込む。
- **UI・ファイル操作関連**
  - 従来の OS のような「階層型ツリー（フォルダーツリー）」は排除し、タグと検索によるフラットな閲覧に特化する。
  - ドラッグ＆ドロップによるカードの手動自由配置はサポートせず、更新順・名前順・関連度順の自動ソートのみとする（ピン留めしたノートの順番は `.taggo.json` で決める）。
  - 既存の Markdown ファイルへ書き込むのは、編集画面での保存と、ページの名前の変更に伴う参照の書き換えだけとする。画像の加工や、本文の自動整形は行わない。
  - 編集画面は Markdown を書いたまま保存する。文書として編集して Markdown へ書き戻す方式（完全な WYSIWYG）にはしない。保存のたびにリストの記号や空行などが書き換わり、ノートに意図しない差分が出るため。
  - 複数のノートを選択してまとめて操作する機能は持たない。
  - ファイルの新規作成は、まだ無いページで「md ファイルを作成する」を押した場合と、検索結果の上の「`タグ.md` を作成する」を押した場合と、編集画面に画像を貼り付けた場合と、ピン留めを保存する `.taggo.json` に限る。
  - サブフォルダの中のノートは扱わない。
- **対応フォーマット関連**
  - 音声ファイルは扱わない。走査・検索・タグ管理・表示のいずれの対象にもしない。
  - 画像ファイルは走査・検索・タグ管理の対象にしない。一覧にも出さず、Markdown の本文に埋め込まれたものを表示するだけとする。
