# 開発ドキュメント

## 動かし方

taggo は Windows 専用です。動作を確かめられるのが Windows だけのため、ほかの OS 向けのコードは持ちません。

### 必要なもの

- Windows 10 以降
- Go 1.26 以上
- Node.js 20 以上
- [Wails CLI](https://wails.io/) v2

```sh
go install github.com/wailsapp/wails/v2/cmd/wails@latest
```

### ビルドと実行

```powershell
make build                  # build/bin/taggo.exe を作る
.\build\bin\taggo.exe       # 起動する

.\build\bin\taggo.exe --folder C:\Users\me\Documents\notes   # フォルダを指定して起動する
```

開発中はホットリロードが使えます。

```sh
make dev
```

なお `wails dev` は GET をすべて Vite の開発サーバーへ転送し、開発サーバーが 404 か 405 を返したときにだけ Go 側のハンドラーへ委譲します。

Vite は未知のパスへ SPA フォールバックで `index.html` を 200 で返してしまうため、`frontend/vite.config.ts` のプラグインで `/taggo/` 以下だけを 404 にして、本文中の画像の配信要求が Go 側へ届くようにしています。

#### make のインストール

標準の Windows には `make` が入っていないため、以下の手順でインストールします。

```powershell
# GNU Make を入れる
winget install GnuWin32.Make
# インストール後、C:\Program Files (x86)\GnuWin32\bin を PATH に追加する
```

### テスト

```sh
make test   # Go のテスト
make lint   # gofmt / go vet / tsc --noEmit
```

### リリース

バージョン番号は [セマンティックバージョニング](https://semver.org/lang/ja/) に従います。`v1.2.3` の形式（プレリリースは `v1.2.3-rc.1`）のタグを push すると、GitHub Actions（`.github/workflows/release.yml`）が Windows 向けの exe をビルドし、GitHub のリリースへ添付します。

1. `CHANGELOG.md` の先頭に新しいバージョンの節（`## [1.2.3] - 日付`）を足し、末尾にそのリリースへのリンクを書く（この節がリリースノートになる）
2. `wails.json` の `info.productVersion` を新しいバージョンにする（ローカルビルド用。Actions ではタグの値で上書きする）
3. コミットしてタグを付け、push する

```sh
git tag v0.1.0
git push origin main v0.1.0
```

- タグが SemVer の形式でないとき、`CHANGELOG.md` にそのバージョンの節が無いとき、テストが落ちたときはリリースを作りません。
- `-` を含むタグはプレリリースとして公開します。

## 設計

- 一覧・検索・タグ管理の対象は、開いたフォルダの直下にある Markdown（`.md` / `.markdown`）だけです。走査もウォッチャーもサブフォルダの中と Markdown 以外のファイルは無視します（ウォッチャーは例外として `.taggo.json` の変更を拾います）。
- ノートのファイル名（拡張子を除く）がタグを表します（`model.PageTag`）。store はタグのキー（`model.TagKey`。小文字にして空白の連なりをまとめたもの）からそのページを引く索引 `tagPages` を持ちます。サブフォルダを読まないのは、同じ名前のページがフォルダ違いで並ばないようにするためです。
- ノートのタグは、本文の `[[タグ]]`（`meta.bodyTags`。コードブロックとインラインコードの中は除く）だけを `model.Entry.Tags` に入れます。Front Matter は使いません。先頭の `---` で囲んだブロックは、見出しや抜粋に紛れ込まないよう `meta.StripFrontMatter` で本文から外すだけで、中身は読みません（YAML のライブラリも使っていません）。
- taggo はノートを書き換えません。タグの編集・一括編集の機能は持たず、ファイルを新しく作るのは「まだ無いページ」か検索結果の上の作成ボタンから md ファイルを作るときと、`.taggo.json` だけです。
- 本文の `[[タグ]]` は、プレビューでは remark プラグイン（`frontend/src/bracketTags.ts`）がリンクに変え、`data-tag` 属性でふつうのリンクと見分けます。
- プレビューのリンクは `MarkdownPreview` の `a` で 3 種類に分けて描きます。`[[タグ]]` とノートへのリンクはアプリの中でたどるので下線を付けず（`INTERNAL_LINK`）、`http(s):` と `mailto:` の外部リンクは下線と末尾の「↗」を付けて（`EXTERNAL_LINK`。画像を囲むリンクには「↗」を付けない）、既定のブラウザで開きます（`BrowserOpenURL`。`target="_blank"` だと WebView2 が自前のウィンドウを開くため）。WebView にはステータスバーが無いので、外部リンクの行き先はツールチップで見せます。
- プレビューの下端の文字数は、`MarkdownPreview` が読み込んだ本文を `DetailPanel` が受け取って数えます。改行は数えず、絵文字や結合文字が 2 文字以上にならないよう `Intl.Segmenter` で書記素ごとに数えます。
- まだ無いページ：`[[タグ]]` や行き先の無い Markdown のリンクをたどると、`App.TagPage` / `App.LinkedPage` が「まだ無いページ」のエントリ（`model.NewMissing`。`Missing` が true で、BuntDB には載せない）を返します。画面はそれを一覧の外のノートとして開き、本文の代わりに「md ファイルを作成する」ボタンを出します。検索結果の先頭にタグのページが無いとき（`Result.Head` が 0）も、画面は検索語で `App.TagPage` を呼び、まだ無いページが返れば結果の上に作成ボタン（`NewTagPageBar`）を出します。
  - `App.RelatedPages` は、まだ無いページのパスでも `store.Related` に仮のエントリを渡すので、そのページを指しているノート（リンク元）が並びます。
  - ボタンは `App.CreatePage` を呼び、見出しだけのファイルを作ってエディタで開きます。ウォッチャーが作ったファイルを拾うと、同じパスのエントリが届くので、画面は開いているページを本物のノートに差し替えます。
  - 扱うパスは開いているフォルダ直下の `.md` / `.markdown` に限ります（`App.checkPagePath`）。ファイル名に使えないタグは `model.TagFileName` で断ります。
- Markdown の本文が正（Single Source of Truth）です。アプリ側にデータベースを保存しません。
- 検索は Pure Go の [BuntDB](https://github.com/tidwall/buntdb) をインメモリで使い、起動時・フォルダ選択時にフォルダ直下の Markdown を走査して展開します。終了時にメモリごと破棄されます。
  - 検索バーの文字列は、空白で区切った語の並びとして読みます（`internal/search`）。語をすべて含むノートが結果で、条件式や `#タグ` の記法はありません。
  - 入力全体がタグのキーと一致するときは、そのタグのページを `Result.Entries` の先頭に置き、その件数を `Result.Head` で返します。検索語が無いときは、ピン留めしたノートを同じように先頭に置きます。グリッド（`CardGrid`）は先頭の `Head` 件と残りを別の行に並べます。
- 本文中の画像は DB に載せず、`/taggo/image?path=…` で配信します。配信するのは、開いているフォルダ配下（シンボリックリンクの実体も含めて確かめる）にあり、先頭バイトから判定した形式がブラウザで表示できる画像（`internal/imagefile`）のファイルだけです。拡張子は見ません。中身がクラウド上にしか無い画像は、属性を見て配信を断ります。
- カードのサムネイル（`model.Entry.Thumbnail`）は走査時に本文から取り出します。コードブロックの外で最初に現れる Markdown の画像（ローカルのパスか http(s) の URL）か YouTube 動画の URL で、画像は書かれたままのパスを持ち、YouTube は動画 ID から `https://i.ytimg.com/vi/<ID>/mqdefault.jpg` を組み立てます。ノートからの相対パスの解決はプレビューと同じ `frontend/src/notePath.ts` で行い、ローカルの画像は `/taggo/image` で配信します。読み込めなければカードは本文の抜粋に戻ります。
- カードのタグ欄は高さを 4 行ぶんに決めてあり、何個収まるかは描画してから実際にあふれているかを測って決めます（`Card.tsx` の `CardTags`）。収まらない分は「+N」で数を示し、タグ欄に乗ると全部を重ねて見せます。
- 本文中の画像をクリックすると、`DetailPanel` の上に `ImagePreview` を重ねて開きます。画像はノートではないので詳細プレビューの履歴には積まず、閉じると同じスクロール位置の本文へ戻ります。
- RAM の消費を抑えるため、1 回の走査で展開する件数に上限（2 万件）を設けています。上限を超えたフォルダは走査順（フォルダ直下のファイル名の順）の先頭だけを読み込み、最後に読んだファイルの相対パスを再開位置として覚えます。「続きを読み込む」ではその位置から次の分を走査し、今の DB へ追記します。
  - 上限に達したあともディレクトリの列挙だけは最後まで続け、残りの件数を数えます。ファイルは開かないので、クラウド同期フォルダでもダウンロードは起きません。
  - ウォッチャーは、再開位置より後ろ（まだ読み込んでいない範囲）のファイルの変更を無視します。そうしないと、その 1 件だけが一覧に紛れ込むためです。
- ファイルウォッチャーが外部エディタによる変更も検知し、該当レコードを同期・削除します。
- 設定（`internal/settings`）は `%APPDATA%\taggo\settings.json`（`os.UserConfigDir()` の下）に JSON で保存します。持つのは起動時に開くフォルダ・一覧の既定の並び順・走査の上限件数・テーマだけで、消えても既定値に戻るだけのものに限ります。
  - 設定を一度も保存しなければファイルは作りません。前回開いたフォルダ（`lastFolder`）は、起動時のフォルダを「前回開いたフォルダ」にしているときだけ `OpenFolder` のたびに書き込みます。
  - 書き込みは同じフォルダの一時ファイルへ書いてから置き換えます。読み込み時に知らない値や範囲外の値は項目ごとに既定値へ直し、JSON として壊れていれば `settings.json.bak` へ退避して既定値で起動します。
  - 起動時に開くフォルダは、コマンドライン引数 → 設定 → 何も開かない、の順に決めます（`App.OpenStartupFolder`）。フォルダが見つからないなどの警告は、起動フックの時点では画面がイベントを受け取れないため、画面から `TakeStartupWarnings` で取りに来てもらいます。
  - 並び順とテーマを最初の描画から反映するため、フロントエンドは設定を読んでから React を描きます（`main.tsx`）。
- 関連ページ（`store.Related`）は、グループ（`RelatedGroup`）の並びとして返します。リンク元のグループ（開いているノートが表すタグを持つノート `tagged` と、Markdown のリンク元 `backlinks` を合わせたもの）、付いているタグごとのグループ（タグの順）、Markdown のリンク先のグループの順です。
  - タグのグループは、先頭にタグのページ（`Page`。まだ無ければ `Path` が空）、後ろにそのタグを持つノート（逆引き索引 `tagged`）を、開いているノートと重なるタグの多い順・更新日時の新しい順に並べます。
  - 並べたノートは「表示済み」として覚え、後のグループには出しません。1 グループは `groupLimit`（24 件）までで、超えた分は `More` に数だけを入れます。
  - 本文の色分けに使う、行き先の無いリンク（`MissingLinks`）とページの無いタグ（`MissingTags`）は、グループとは別に返します。後のグループで表示が省かれても、本文の色が変わらないようにするためです。
  - 画面（`RelatedPages`）は本文の下に、グループごとのカードのグリッドとして描きます。カードの抜粋・サムネイルは一覧のカードと同じ `NotePreview` を使います。
- ピン留めは開いたフォルダ直下の `.taggo.json`（`internal/folderconf`）にファイル名の並びとして保存します。フォルダの Wiki の見せ方なので、`%APPDATA%` ではなくノートと一緒に置いています。
  - 書き込むときは毎回ファイルを読み直し、taggo の知らない項目は残します。JSON として壊れていれば書き換えずにエラーにします。一時ファイルは `.taggo.json.taggo-XXXX` で、ウォッチャーは自分の書き込みとして無視します。
  - ウォッチャーが `.taggo.json` の変更を拾うと読み直し、`pins:changed` イベントで画面に引き直させます。中身がクラウド上にしか無いときは読みません。
- クラウド同期フォルダの「オンラインのみ」のファイルは、属性で見分けて開きません。判定の前提として、起動時にプレースホルダーを通常ファイルとして見せる設定（`RtlSetProcessPlaceholderCompatibilityMode`）へ固定しています。そうしないと `os.Stat` が属性を問い合わせるだけで済まず、ファイルを開きに行くためです。
- 同期フォルダの属性は、更新日時を変えずに変わるためウォッチャーでは気付けません。そのため、中身を開く直前に毎回属性を確かめ直します。なお `FILE_FLAG_OPEN_NO_RECALL` を付けて開いても、Dropbox ではダウンロードが始まるため、安全網には使えません。
- リンクカードの内容は Go 側（`internal/linkcard`）で取得します。WebView からは CORS のため他サイトの HTML を読めないためです。接続先は名前解決後のアドレスで判定し、ローカルネットワークには接続しません。YouTube は地域によって同意画面へ飛ばされ、X はブラウザ以外に OGP を返さないため、この 2 つは oEmbed を使います。
- 画面のスタイルは Tailwind CSS のユーティリティで組み立てています。独自に書く CSS は `frontend/src/styles/global.css` の配色トークン（`@theme`）と要素の既定値だけです。配色は `frontend/src/theme.ts` が `<html data-theme="light|dark">` を付けて切り替え、トークンと Tailwind の `dark:` バリアントはこの属性を見ます。テーマが「OS に合わせる」のときは OS の設定を解決した値を入れ、OS の切り替えにも追従します。タイトルバーの配色は Go 側（Wails の `WindowSet*Theme`）で合わせます。アイコンは [Heroicons](https://heroicons.com/) を使っています。

### パッケージ構成

| パッケージ           | 役割                                                 |
| -------------------- | ---------------------------------------------------- |
| `internal/model`     | 共有するデータ型とタグの正規化・ファイル名とタグの対応 |
| `internal/meta`      | Markdown の本文からタグ（`[[タグ]]`）・見出し・抜粋・リンクを読み取る |
| `internal/store`     | BuntDB への展開と検索・タグ索引・リンクの関連付け・ピン留めの並び |
| `internal/search`    | 検索バーの文字列を問い合わせへ変換する               |
| `internal/scan`      | フォルダ直下の走査とメタデータの並列読み取り         |
| `internal/watcher`   | ファイル変更の検知                                   |
| `internal/folderconf` | フォルダ直下の設定ファイル（`.taggo.json`。ピン留め）の読み書き |
| `internal/cloudfile` | クラウド同期フォルダとオンラインのみのファイルの判定 |
| `internal/imagefile` | 本文中の画像の形式判定（配信してよい画像か）         |
| `internal/linkcard`  | リンクカードに出す OGP / oEmbed の取得とキャッシュ   |
| `internal/settings`  | 設定ファイル（`%APPDATA%\taggo\settings.json`）の読み書き |
| `internal/app`       | フロントエンドへ公開する API と本文中の画像の配信    |
| `frontend`           | React + TypeScript + Vite + Tailwind CSS の UI       |
